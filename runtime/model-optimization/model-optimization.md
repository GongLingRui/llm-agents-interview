# Model Optimization（Canonical）

> **一句话主题**：在可接受质量下，通过改变**模型表示、模型族选择与解码协作方式**降低 Agent 的推理成本与延迟，并用评测门禁证明权衡成立。
>
> **状态**：Canonical · **Last reviewed**: 2026-10  
> **受众**：要在生产中压低 Token/GPU 成本、控制交互延迟、设计多模型策略的工程师  
> **前置依赖**：[LLM Inference](../llm-inference/README.md)（服务侧延迟结构）；建议 [Evaluation](../../production/evaluation/README.md)、[foundations/llm](../../foundations/llm/README.md)  
> **下游枢纽**：Agent 生产部署、多模型路由策略、成本治理

## 1. Overview：在系统中的位置

Agent 的单次用户任务常展开为 **N 步 Loop**（推理 → 工具 → 观察 → 再推理）。每一步都消耗：

| 资源 | 典型来源 |
|------|----------|
| Token 费用 / GPU 时间 | 模型前向与解码 |
| 显存 | 权重 + KV（KV 细节见 Inference） |
| 墙钟延迟 | TTFT + 解码 + 工具等待 |
| 质量风险 | 错误工具调用、幻觉、策略漂移 |

**Model Optimization** 回答的是：**在不改 Agent 控制回路语义的前提下，如何换「更便宜但仍够用」的模型表示或模型组合**。

```text
用户任务
  → Agent Loop（core）
      → 每步 LLM 调用
           ├─ Inference Runtime：批处理 / 缓存 / 队列（怎么跑）
           └─ Model Optimization：量化 / 蒸馏 / 投机 / 路由（跑哪个表示、哪个规模）
      → Evaluation：证明质量可接受（是否允许上线）
```

**关键分界**：Inference 优化「同一模型资产如何高效服务」；Model Optimization 优化「资产本身与资产选择策略」。二者常联用，但知识应分目录维护。

## 2. Mental Model：优化对象与杠杆

### 2.1 四个杠杆

| 杠杆 | 改什么 | 不改什么 | 典型收益 |
|------|--------|----------|----------|
| **量化** | 权重/激活数值精度 | 模型结构与训练目标（多数情况） | 显存↓、吞吐↑、成本↓ |
| **蒸馏** | 用大模型监督训练更小模型 | 推理服务拓扑 | 单次调用成本↓、可边缘部署 |
| **投机解码** | 草稿模型 + 目标模型协作解码 | 目标模型参数分布（理想情况） | 延迟↓，质量≈目标模型 |
| **路由到小模型** | 按请求/步选择模型 | 最大模型能力上限 | 平均成本↓，尾部质量靠大模型兜底 |

### 2.2 优化目标向量

生产上几乎从不优化单一标量。最小目标向量：

```text
J = (Quality, Latency_p50/p95, Cost_per_task, Memory_footprint, Risk)
```

- **Quality**：任务成功率、工具参数正确率、轨迹合规率（见 Eval）
- **Latency**：对交互 Agent，p95 往往比均值更重要
- **Cost_per_task**：单步成本 × 期望步数（步数爆炸会抵消单步优化）
- **Memory**：决定能否同卡多副本、能否上更大上下文
- **Risk**：安全/合规切片上的不可接受退化

### 2.3 Agent 视角的特殊性

单轮聊天助手可只看「答案准确率 × 单次延迟」。Agent 还必须看：

1. **多步放大**：单步质量下降 2% 可能使工具误调用连锁失败，任务成功率下降远超 2%。
2. **结构化输出脆弱性**：量化/小模型常先伤 JSON/schema 遵从，再伤开放生成。
3. **步数弹性**：更便宜的模型若需要更多反思/重试步，总成本可能上升。
4. **异构步**：路由、工具选择、长推理、摘要压缩对模型能力需求不同——适合异构模型组合。

| 流式、工具中断 | Inference | 如何边生成边交互 |
| 限流、队列、多租户 | Inference | 如何在容量约束下公平服务 |

- 谈「vLLM 的 continuous batching 如何提吞吐」→ Inference。

- 谈「草稿模型与目标模型如何配对、接受率多少才划算」→ 本文机制；接受率监控仪表可挂 Observability / Inference。

**禁止**：在本文展开批处理算法、PagedAttention、前缀缓存命中率调优长文。需要时只链到 Inference 模块。

## 4. 量化（Quantization）

### 4.1 定义

**量化**把浮点权重（常为 FP16/BF16）映射到更低比特整数或低精度浮点（INT8、INT4、FP8 等），推理时用低精度矩阵乘（或反量化后计算）降低显存与带宽压力。

### 4.2 常见形态（工程分类，非厂商目录）

| 形态 | 大致含义 | Agent 关注点 |
|------|----------|--------------|
| **PTQ**（Post-Training Quantization） | 训练后校准/量化，成本低 | 最快落地；需校准集覆盖工具调用分布 |
| **QAT**（Quantization-Aware Training） | 训练中模拟量化噪声 | 质量更好但成本高；常与 Fine-tuning 交叉 |
| **权重量化为主** | 只压权重，激活仍较高精度 | 显存收益大、实现成熟 |
| **权重+激活量化** | 进一步压算力 | 对异常激活敏感，工具调用易抖 |
| **KV Cache 量化** | 压缓存精度 | 长上下文 Agent 显存关键；机制细节属 Inference 落地 |

代表性方法族（机制映射，非教程）：GPTQ / AWQ 等面向「训练后权重量化 + 校准」；SmoothQuant 等处理激活离群值以便 W8A8。参见文末 References。

### 4.3 对 Agent 行为的影响路径

```text
精度下降
  → logits 分布轻微变形
  → （1）开放文本略变  （2）JSON/工具名/枚举更易错  （3）长链推理更易中途偏离
  → 工具参数错误 ↑ → 重试/重规划 ↑ → 步数与成本可能反升
```

**优先评测切片**（必须，链 Eval）：

1. 工具选择准确率 / schema 合规率  
2. 多步任务成功率（不只是单轮问答）  
3. 安全与拒绝策略切片（量化常非均匀损伤）  
4. 长上下文中段信息利用（与 Context Engineering「Lost in the Middle」叠加）

### 4.4 何时量化划算

**倾向做**：

- 显存是硬约束（要同卡跑更大上下文或更多副本）
- 任务以检索+短推理+工具调用为主，对「创造性长文」不敏感
- 有代表性离线评测集，可设回归门禁

**倾向不做 / 缓做**：

- 尚未有评测门禁，仅凭 demo「看起来差不多」
- 高风险不可逆动作路径（支付、删库）尚未加 Verification / HITL
- 模型已是小尺寸，量化边际收益小却引入质量方差

### 4.5 失败模式（量化）

| Symptom | Cause | Impact | Detection | Mitigation |
|---------|-------|--------|-----------|------------|
| 工具 JSON 偶发损坏 | 低比特伤结构化生成 | 重试爆炸 | schema 失败率监控 | 抬精度；或仅非关键路径用量化模型 |
| 长任务中后段崩溃 | 误差累积 | 成功率陡降 | 按步数切片评测 | 关键步 escalate 到高精度模型 |
| 「平均差不多、尾部很差」 | 校准集未覆盖尾部 | 线上事故 | p95 质量 / 安全切片 | 重采校准；保留 BF16 回退 |
| 同 prompt 输出抖动变大 | 数值路径不稳定 | 难复现、难调试 | 温度=0 下重复跑方差 | 固定种子+服务侧确定性配置；记录模型指纹 |

## 5. 蒸馏（Distillation）

### 5.1 定义

**知识蒸馏**让学生模型学习教师模型的行为分布（logits、中间表示、或轨迹级决策），目标是用更小/更快的学生在目标任务分布上逼近教师。

与 **Fine-tuning** 的边界：蒸馏强调「模仿教师」；SFT 强调「拟合标注数据」。实践中常重叠（用教师生成数据再 SFT），但决策理由不同：蒸馏为压缩与成本，SFT 为行为对齐与格式学习。训练配方细节 → Fine-tuning。

### 5.2 Agent 常用蒸馏形态

| 形态 | 教师信号 | 适合角色 |
|------|----------|----------|
| **输出蒸馏** | 最终答案 / 结构化 tool call | 路由、分类、简单工具选择 |
| **轨迹蒸馏** | 多步 Thought–Action–Observation 轨迹 | 短程 Agent 策略压缩 |
| **偏好/排序蒸馏** | 教师对候选排序 | 降低错误动作概率 |
| **专用技能蒸馏** | 仅工具选择、仅摘要、仅 SQL 生成 | 异构小模型集群 |

### 5.3 何时蒸馏优于「直接上小开源模型」

- 教师在**你的任务分布**上已证明可用，需要同分布压缩  
- 需要保留特定 tool schema / 内部黑话 / 合规话术  
- 希望学生继承教师的「拒绝策略」而非通用小模型默认行为  

何时不优先蒸馏：

- 任务可用 Prompt + RAG + 现成 API 小模型解决，且无数据飞轮  
- 没有可持续的教师轨迹数据管线（蒸馏会变成一次性玩具）  
- 真正瓶颈在 Inference 调度而非模型大小

### 5.4 失败模式（蒸馏）

| Symptom | Cause | Impact | Detection | Mitigation |
|---------|-------|--------|-----------|------------|
| 学生只会「常见路径」 | 轨迹数据长尾不足 | 罕见工具/错误恢复差 | 长尾切片评测 | 主动采难例；保留 escalate |
| 模仿教师废话 | 轨迹含无效反思 | 延迟与成本升 | 步数对比教师 | 清洗轨迹；缩短监督信号 |
| 格式对、决策错 | 只蒸馏表面 schema | 静默错误 | 语义级 tool 参数评测 | 加强动作结果反馈数据 |
| 与线上分布漂移 | 教师/产品已变，学生未更新 | 质量 silently 下降 | 周期性回归 + 数据新鲜度 | 蒸馏纳入发布火车 |

## 6. 投机解码（Speculative Decoding）

### 6.1 定义

**投机解码**用廉价**草稿模型（draft）**快速提出一段候选 token，再由**目标模型（target）**并行验证；按接受规则提交前缀，拒绝后从分歧点由目标模型纠正。理想情况下，**输出分布与单独跑目标模型一致**（或可控近似），但墙钟延迟下降。

### 6.2 为何对 Agent 有吸引力

- Agent 交互延迟常被「解码 token 数」主导；工具调用前后的长思考尤其痛。  
- 许多步需要「大模型质量」，但不想付满速自回归的延迟。  
- 与「换小模型」不同：投机解码的目标是**保目标模型质量**，换的是时间。

### 6.3 收益公式（定性）

```text
加速比 ≈ f(草稿质量, 接受率 α, 草稿/目标成本比, 验证并行度)
```

- **α 高**：草稿常与目标一致 → 加速明显  
- **α 低**：反复拒绝 → 可能负优化（多付草稿成本）  
- **分布偏移大的任务**（强约束 JSON、罕见工具名）：α 可能骤降  

### 6.4 与 Inference 的挂载点

- **机制选择**（要不要投机、草稿怎么选、质量一致性要求）→ 本文  
- **服务实现**（如何在引擎内调度 draft/target、与 continuous batching 共存）→ Inference  
- **观测**：接受率、每请求 draft token 数、端到端 TTFT/TPOT → Observability，指标定义两边共享

### 6.5 草稿模型选型原则

1. 与目标同 tokenizer 族或可对齐的词表（否则工程代价高）  
2. 足够快：通常显著小于目标；过弱则 α 崩  
3. 在**你的** Agent 轨迹分布上校准 α，而不是只看开放生成基准  
4. 对结构化输出：可考虑「草稿只猜内容、关键结构由目标主导」等变体（产品相关，标 TODO: Verify 厂商能力）

### 6.6 失败模式（投机解码）

| Symptom | Cause | Impact | Detection | Mitigation |
|---------|-------|--------|-----------|------------|
| 延迟不降反升 | α 低 | 浪费算力 | α 与延迟联合监控 | 换草稿或关闭投机 |
| 「质量变了」争议 | 近似投机 / 实现 bug | 信任危机 | 对照关闭投机的 A/B | 坚持 lossless 模式；修实现 |
| 仅 benchmark 好看 | 开放文本 α 高、工具调用 α 低 | 上线翻车 | 按任务类型分桶 α | 工具步禁用或换草稿 |
| 运维复杂度上升 | 双模型版本耦合 | 发布易错 | 版本矩阵测试 | 绑定 draft–target 版本对 |

## 7. 路由到小模型（Routing / Cascade）

### 7.1 定义

**路由**根据请求特征、中间状态或置信度，把一步调用派给不同规模/成本的模型；**级联（Cascade）**通常从小到大尝试，不满意再升级。

这与 Inference 模块的「多模型路由、降级、超时」规划主题相邻：**策略与质量边界在本文；超时/队列/fallback 执行在 Inference**。

### 7.2 常见策略

| 策略 | 机制 | 优点 | 风险 |
|------|------|------|------|
| **静态规则** | 按意图/工具类型/租户套餐硬编码 | 可解释、易审计 | 规则腐化 |
| **轻量分类器路由** | 小模型/传统分类器预测难度 | 平均成本低 | 误路由到过小模型 |
| **置信度级联** | 小模型先答，低置信 escalate | 自适应 | 置信度校准差 |
| **步类型路由** | 路由/摘要用小；规划/编码用大 | 贴合 Agent | 需清晰步标签 |
| **预算路由** | 剩余成本/延迟预算决定模型 | 控总成本 | 末期质量塌方 |

### 7.3 Agent 推荐的默认分解

许多生产 Agent 可先采用**步类型路由**（再进化到学习型路由）：

```text
意图分类 / 简单 FAQ / 观察摘要     → 小模型
工具选择与参数填充（中等）         → 中模型或量化大模型
复杂规划 / 安全敏感 / 失败恢复     → 大模型（高精度）
最终用户可见长文                  → 按 SLA 选择
```

### 7.4 与「一律小模型」对比

一律小模型看似最省，但 Agent 上常见反噬：

- 工具错误 → 重试 → 步数 × 成本上升  
- 用户等待更多轮澄清 → 产品延迟体感变差  
- 安全误判成本远高于 Token 节省  

**正确比较单位是「完成任务的期望总成本与成功率」**，不是「单次调用单价」。

### 7.5 失败模式（路由）

| Symptom | Cause | Impact | Detection | Mitigation |
|---------|-------|--------|-----------|------------|
| 成本降、成功率崩 | 过度路由到小模型 | 业务失败 | 任务成功 vs 成本曲线 | 提高 escalate 阈值；关键意图锁大模型 |
| 几乎总 escalate | 阈值过严 / 小模型过弱 | 白付双倍 | escalate 率 | 调阈值或换小模型 |
| 振荡路由 | 状态机每步改模型导致风格分裂 | 用户困惑 | 轨迹审计 | 会话粘性；同子任务锁定模型 |
| 影子成本 | 路由模型本身很贵 | 假节省 | 计入路由器成本 | 用极轻分类器或规则 |

## 8. 质量–成本权衡（Quality–Cost Tradeoffs）

### 8.1 决策框架

对任一优化提案，强制回答五问：

1. **改的是哪条杠杆？**（量化 / 蒸馏 / 投机 / 路由 / 组合）  
2. **质量代理指标是什么？**（必须可测，链 Eval）  
3. **成本与延迟如何按任务聚合？**（含步数期望）  
4. **不可接受的退化切片？**（安全、支付、合规……）  
5. **回退路径？**（特征开关、按租户、按意图）

### 8.2 帕累托视角

可行方案落在近似帕累托前沿上：

```text
更高质量  ←——————→  更低成本
        ↖ 延迟 / 复杂度也占维度
```

工程上选点而非「找唯一最优」：

- **延迟敏感交互**：投机解码、中等量化、关键步大模型  
- **批处理离线 Agent**：可更激进量化 / 小模型，换吞吐  
- **高风险域**：质量与风险权重上调，成本杠杆后置  

### 8.3 组合拳（推荐顺序）

经验顺序（可按数据调整）：

1. **先量任务**：建立 Eval 基线与成本仪表（无此则后续都是赌博）  
2. **再路由**：把明显简单步剥给小模型（收益常大于一刀切量化）  
3. **再量化**：对保留的大模型路径做 PTQ，跑回归门禁  
4. **再投机**：在大模型路径上换延迟，监控 α  
5. **最后蒸馏**：有稳定轨迹飞轮再上学生模型，替代部分路由目标  

**反模式**：无评测先蒸馏一个月；或同时上四条杠杆导致无法归因。

### 8.4 成本模型（最小）

```text
E[cost_task] ≈ Σ_steps E[cost(model_s, tokens_s)] + E[tool_cost] + E[retry_penalty]
E[latency_task] ≈ Σ_steps E[llm_latency_s] + E[tool_wait]  （可并行步另计）
```

优化单步 `cost(model)` 时必须估计对 `retry_penalty` 与 `steps` 的二阶效应。

## 9. Agent 特有优化点

### 9.1 按步优化，而非按会话一刀切

会话级固定模型简单，但浪费大。步级策略需要：

- 步类型标签（planner / actor / summarizer / verifier）  
- 每类的模型绑定与覆盖率监控  
- 失败时的 escalate 边  

### 9.2 观察压缩与小模型

长 Observation 可用小模型摘要后再喂大模型——这是 **Context Engineering** 与本文的交界：

- 「摘要模型用谁、质量如何验」→ 本文 + Eval  
- 「摘要塞进上下文的位置与预算」→ Context Engineering  

### 9.3 Verification 用不同模型

Verifier 不必等于 Actor：

- 小模型做格式/规则检查  
- 大模型或工具做语义/事实核查  
- 避免「同一量化模型既犯错又自证正确」的耦合失败  

详见 Reasoning/Planning 中 Verification 概念；实现挂钩 Eval 与 Tool Use。

### 9.4 缓存命中与模型指纹

前缀缓存等属 Inference，但**模型版本/量化版本变化会使缓存键失效或行为漂移**。优化发布必须包含：

- 模型指纹（权重哈希、量化方案、草稿版本）  
- 缓存命名空间隔离  
- 金丝雀流量上的质量对比

## 10. 与 Evaluation 的强制链接

优化提案未经 Eval 不得称为「可上线」。最小门禁：

| 门禁 | 含义 |
|------|------|
| **任务成功回归** | 核心任务集成功率不低于基线 − ε |
| **工具面回归** | schema 合规、参数正确、危险工具误触 |
| **切片不崩** | 安全 / 长尾意图 / 长上下文切片 |
| **成本与延迟报表** | 同任务集上 E[cost]、p95 latency |
| **可回退** | 开关与版本回滚演练通过 |

评测设计（数据集、rubric、offline/online）全文见 [`production/evaluation`](../../production/evaluation/README.md)。本文只要求：**优化实验与 Eval 使用同一任务定义与同一成功标准**。

**Online**：影子流量对比、按意图分桶的 escalate 率、α（投机）、量化模型错误码分布——与 Observability 共用仪表，判据仍归 Eval 治理。

## 11. 生产架构挂钩（不复制邻模块）

```text
                    ┌─ Model Registry（指纹、量化方案、draft 绑定）
Request → Router ───┼─ Inference Gateway（批处理/缓存/限流）──→ Engines
                    └─ Policy（租户预算、风险级、特征开关）
                              │
                              ▼
                         Eval Gates / Canary
```

组件职责：

- **Model Registry**：资产真相源（含「BF16 vs INT4」变体）  
- **Router Policy**：本文策略的配置化  
- **Inference Gateway**：执行与性能（细节见 Inference）  
- **Eval Gates**：发布阻断  

Security：降低模型能力不等于降低权限；工具鉴权与沙箱仍按 [`production/security`](../../production/security/README.md) / [`runtime/sandbox`](../sandbox/README.md)。

## 12. 决策伪代码

```text
function choose_optimization(agent_profile, baseline_eval):
  require baseline_eval.gates_defined()

  candidates = []

  if agent_profile.has_obvious_easy_steps():
    candidates.add(StepTypeRouter(small=S, large=L))

  if memory_bound(L) or cost_bound(L):
    candidates.add(Quantize(L, scheme=PTQ_candidate))

  if latency_bound(L) and quality_must_match(L):
    candidates.add(Speculative(draft=D, target=L))

  if stable_teacher_traces() and repeated_subskills():
    candidates.add(Distill(teacher=L, student=S2, skills=...))

  for c in candidates:
    score = eval_suite.run(c)   # 同一成功标准
    if not score.pass_gates(): reject c
    else rank by (Δcost, Δlatency, Δrisk)

  return pick_pareto(candidates)  # 单次只上有限杠杆，保证可归因
```

## 13. Trade-offs（定性总表）

| 手段 | 质量风险 | 延迟 | 成本 | 复杂度 | 归因难度 |
|------|----------|------|------|--------|----------|
| 量化 | 中（结构化更敏感） | 常改善吞吐/有时改善延迟 | ↓ | 中 | 低–中 |
| 蒸馏 | 中–高（长尾） | ↓（学生） | ↓↓ | 高（数据） | 中 |
| 投机解码 | 低（理想 lossless） | ↓（α 高时） | 视 α | 中–高 | 中 |
| 路由小模型 | 中（误路由） | 混合 | ↓ 平均 | 中 | 中–高 |
| 多杠杆叠加 | 叠加且难拆 | 不定 | 可能↓ | 很高 | 很高 |

## 14. 与 Fine-tuning / RL 的再边界

| 诉求 | 优先模块 |
|------|----------|
| 同一能力更便宜跑 | **Model Optimization** |
| 改变工具格式/领域行为 | Fine-tuning |
| 偏好对齐、探索学习 | RL |
| 同一权重跑更快更多并发 | Inference |

可组合：先 SFT 出好教师，再蒸馏学生，再量化学生，再在网关上投机——但每个阶段单独设 Eval 门禁。

## 15. Failure Modes 汇总（跨杠杆）

1. **单步更便宜、任务更贵**（重试与步数反噬）  
2. **平均指标好看、切片翻车**（安全/长尾）  
3. **无法归因**（同时上多杠杆）  
4. **版本漂移**（draft/学生/量化方案未钉指纹）  
5. **把 Inference 问题误当模型问题**（队列堵塞却去量化）  
6. **用开放聊天基准代替 Agent 轨迹评测**  

检测信号统一：任务成功、工具合规、escalate 率、α、成本/任务、p95 延迟、切片报警。

## 16. Interview Questions

### Beginner

**Q1. Model Optimization 和 LLM Inference 差在哪？**  
- **短答**：前者改模型表示/选择策略；后者改同一资产的服务效率。  
- **详解**：量化/蒸馏/路由属前者；批处理/KV/限流属后者。  
- **追问**：投机解码落在哪边？  
- **常见错误**：把 continuous batching 写进优化主文当主体。  
- **相关**：§3。

**Q2. 为什么 Agent 不能只看单次调用单价？**  
- **短答**：步数与重试会放大或抵消单步节省。  
- **详解**：用 E[cost_task] 比较。  
- **追问**：如何估计 retry_penalty？  
- **常见错误**：只报 $/1K tokens。  
- **相关**：§8.4。

**Q3. 量化主要省什么？**  
- **短答**：显存与内存带宽，常带来更高吞吐/更低成本。  
- **详解**：不一定等比改善延迟。  
- **追问**：KV 量化算哪类？  
- **常见错误**：认为量化=永远更快。  
- **相关**：§4。

**Q4. PTQ 和 QAT 区别？**  
- **短答**：PTQ 训练后量化；QAT 训练中感知量化噪声。  
- **详解**：PTQ 快，QAT 往往更稳但贵。  
- **追问**：Agent 工具调用场景优先哪个？  
- **常见错误**：无校准直接 INT4 上线。  
- **相关**：§4.2。

**Q5. 蒸馏的教师信号可以是什么？**  
- **短答**：答案、logits、轨迹、排序偏好等。  
- **详解**：Agent 常轨迹/工具调用蒸馏。  
- **追问**：与 SFT 如何区分动机？  
- **常见错误**：把任意微调都叫蒸馏。  
- **相关**：§5。

**Q6. 投机解码为何可能保持质量？**  
- **短答**：目标模型验证草稿，理想下分布与目标一致。  
- **详解**：接受/拒绝机制。  
- **追问**：α 是什么？  
- **常见错误**：把草稿输出当最终答案。  
- **相关**：§6。

**Q7. 什么是 cascade？**  
- **短答**：从小到大尝试，不满意再升级。  
- **详解**：一种路由形态。  
- **追问**：与静态规则路由对比？  
- **常见错误**：忽略路由器自身成本。  
- **相关**：§7。

**Q8. 为何量化常先伤工具调用？**  
- **短答**：结构化约束更脆，logits 微扰易毁 JSON/枚举。  
- **详解**：优先测 schema 合规。  
- **追问**：如何缓解？  
- **常见错误**：只用开放 QA 准确率验收。  
- **相关**：§4.3。

**Q9. 优化上线最小门禁有哪些？**  
- **短答**：任务成功、工具面、切片、成本延迟、可回退。

- **追问**：谁拥有门禁定义？  
- **常见错误**：demo 通过即上线。  
- **相关**：§10。

**Q10. 「路由到小模型」优化的是什么？**

**Q37. 设计可归因的优化实验序列。**  
- **短答**：一次一个主杠杆；阶乘设计慎用；保留开关。  
- **详解**：§8.3 顺序。  
- **追问**：必须同时上两个时？  
- **常见错误**：大爆炸发布。  
- **相关**：§8.3、§12。

**Q38. 量化 + 路由 + 投机同时存在，观测如何分层？**  
- **短答**：任务级成功/成本；步级模型选择；引擎级 α 与队列。  
- **详解**：分层才能定位。  
- **追问**：报警如何路由到人？  
- **常见错误**：一个大红灯。  
- **相关**：§11、§15。

**Q39. 何时蒸馏不如直接买更强 API 小模型？**  
- **短答**：无数据飞轮、教师专属行为不重要、维护成本高于差价。  
- **详解**：总拥有成本。  
- **追问**：专属行为例子？  
- **常见错误**：为蒸馏而蒸馏。  
- **相关**：§5.3。

**Q40. 讨论有损投机（近似接受）在 Agent 上的风险。**  
- **短答**：分布偏移可能放大工具错误；需更严 Eval。  
- **详解**：默认偏 lossless。  
- **追问**：何种产品可接受有损？  
- **常见错误**：静默开启近似模式。  
- **相关**：§6。

### System Design

**Q41. 为 Coding Agent 设计模型优化方案（质量优先）。**  
- **短答**：规划/补丁生成用大；检索摘要用小；量化谨慎；投机分语言桶测 α；强 Eval。  
- **详解**：不可逆写操作前 Verification。  
- **追问**：单测失败如何 escalate？  
- **常见错误**：仓库级一律 INT4。  
- **相关**：全文。

**Q42. 为高 QPS 客服 Agent 设计成本优先方案。**  
- **短答**：强路由+级联；FAQ 小模型；投诉/支付锁大模型；PTQ；投机可选。  
- **详解**：切片门禁。  
- **追问**：如何防过度降级？  
- **常见错误**：全量最小模型。  
- **相关**：§7–8、§10。

**Q43. 画出 Model Registry 与 Inference Gateway 的职责切割。**  
- **短答**：Registry=资产与策略元数据；Gateway=调度执行。  
- **详解**：§11 图。  
- **追问**：草稿绑定存在哪？  
- **常见错误**：引擎硬编码模型路径无指纹。  
- **相关**：§11。

**Q44. 从零到一的 90 天优化路线图。**  
- **短答**：D0–30 Eval+成本仪表；D30–60 路由；D60–75 量化门禁；D75–90 投机/蒸馏试点。  
- **详解**：每阶段可回退。  
- **追问**：人员技能缺口？  
- **常见错误**：第 1 周开炼学生模型。  
- **相关**：§8.3、§12。

**Q45. 评审同事方案：同时上 INT4、新学生模型、全局投机、无新评测。**  
- **短答**：拒绝；无门禁不可归因；要求拆分实验并补 Agent 轨迹评测。  
- **详解**：引用失败模式汇总。  
- **追问**：最小可合并子集是什么？  
- **常见错误**：被「预计省 50%」说服。  
- **相关**：§10、§15。
