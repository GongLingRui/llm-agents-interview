# 文档质量标准

> 主题：什么叫「可以合并进本知识库」的文档。

## 总则

本仓库要的是 **可维护的工程知识**，不是信息聚合页。一篇文档合格的最低标准是：读者读完后能获得可迁移的机制理解或可执行决策。

## 分级

| 级别 | 含义 | 何时允许 |
|------|------|----------|
| Stub | 仅标题/范围/大纲 | Phase 1 架构期；或 PR 首稿 |
| Outline | 有完整提纲与关键定义 | 主题立项后 |
| Draft | 有机制说明，缺部分例子/引用 | 可开 PR 讨论 |
| Canonical | 机制、边界、失败模式、引用齐全 | 可作为模块主文 |
| Evergreen Review | 定期复核过时声明 | 生产关键模块 |

Phase 1 目标：模块 README = Outline 级；规范文档 = Canonical 级。  
工程模块 Canonical（1A）、Practice（2A）与 Research 深潜笔记已落地。后续以 **Evergreen Review** 与有来源增量为主。见 [phase-2-canonical-audit.md](./phase-2-canonical-audit.md)。

## 每篇内容文档必须包含

1. **标题与一句话主题**
2. **受众**（谁该读）
3. **前置依赖**（链到模块）
4. **范围 / 非目标**（Non-goals 必写）
5. **正文结构**（机制 → 工程含义 → 失败模式 → 实践建议）
6. **交叉链接**（上游/下游）
7. **References**（按引用规范）

## 写法标准

### 鼓励

- 用控制流、状态、接口描述 Agent 行为
- 明确权衡（准确率 / 成本 / 延迟 / 复杂度 / 安全）
- 记录失败模式与检测信号
- 把论文/博客主张映射到本仓库模块

### 禁止

- 无机制的工具安利清单
- 大段粘贴官方文档
- 同一主题多处维护两份正文
- 「赋能」「颠覆」等空话开头
- 只有步骤没有「为什么」

## 模块 README 标准（强制）

每个模块 `README.md` 必须有：

- 职责
- 受众
- 前置依赖
- 计划主题清单（文件名级）
- 非目标（明确不写什么）
- 上游 / 下游链接
- 与易混模块的边界说明

## 命名与结构

- 目录 / 文件：`kebab-case`
- 一个文件一个主主题
- 标题层级不超过四级
- 图片/图解放模块内 `assets/`（需要时再建，不预建空目录）

## 审查清单（Reviewer）

- [ ] 落点目录正确（一主题一位置）
- [ ] 依赖声明真实，无跳跃假设
- [ ] Non-goals 能防止范围膨胀
- [ ] 有失败模式或限制说明
- [ ] 引用可追溯
- [ ] 没有与其他 Canonical 文重复
- [ ] 中文表达清晰；必要英文术语保留并在首次出现时解释

## 过时治理

- 涉及 API / 产品能力的文档，文首标注 `Last reviewed: YYYY-MM`
- 厂商实践与框架分析：默认 6 个月复核
- 机制类（Loop / Memory 概念）：默认 12 个月复核，除非领域共识变化
