# AWQ: Activation-aware Weight Quantization for LLM Compression and Acceleration

## Metadata

- Authors / Year / Venue: Lin, Tang, Tang, Yang, Chen, Wang, Xiao, Dang, Gan, Han · 2023 · arXiv:2306.00978
- Links: https://arxiv.org/abs/2306.00978
- Tags: model-optimization
- Last reviewed: 2026-10-07
- Reference: [paper-awq-2023](../../../references/papers.md#paper-awq-2023)

## TL;DR

**激活感知的权重量化**：按激活显著性识别重要权重通道并保护（常通过缩放再量化），强调硬件友好的低比特推理。是压缩/加速选型中的常见对照族；落在 **模型优化层**，不是 Agent Loop。

## Problem setup

低比特权重量化时，并非所有通道同等重要；忽略激活分布会导致「少数关键通道」被同样粗量化，生成与下游任务质量陡降。

## Method / Mechanism

```text
校准激活统计 → 找对输出影响大的权重通道（activation-aware saliency）
             → 对显著通道做保护（如放大后再量化、等效缩放）
             → 得到硬件友好的低比特权重
```

- 核心直觉：**权重量化误差 × 激活幅度** 才决定层输出扰动。
- 与 GPTQ 同属「PTQ 权重量化」谱系，但显著性/保护机制不同；工程选型比拼引擎支持与回归质量，而非论文名。

## How it changes the Agent Loop

- **不改** Loop 状态机与工具契约。
- **改** 单次前向的数值表示与延迟/成本曲线；工具步与长轨迹对量化噪声更敏感。
- Canonical：[model-optimization](../../../runtime/model-optimization/model-optimization.md)；吞吐与并发仍看 [llm-inference](../../../runtime/llm-inference/llm-inference.md)。

## Experiments that matter

- 论文在多种 LLM 与生成/下游任务上对比朴素量化与其它压缩基线，展示激活感知保护的收益（**幅度以原文为准；线上必须自测**）。
- 对工程更重要：低比特路径是否与目标推理栈（内核、算子）匹配。

## Engineering takeaways

1. 选型时并列评 GPTQ/AWQ/厂商方案：同一 Agent 轨迹集、同一 schema 指标。
2. 「硬件友好」只有在你实际用的引擎上成立；无内核则只有压缩无加速。
3. 高风险路径可保留高精度模型；量化模型走可回退意图桶。
4. 与路由组合：简单步小模型，关键步高精度或未量化大模型。

## Limitations & failure modes

- 校准分布漂移 → 显著性估计失效。
- 结构化输出、安全拒绝切片可能非均匀损伤。
- 与 KV 量化、激活量化是不同旋钮，勿混为一谈。

## When you should / shouldn't use it

| 应该 | 不应该 |
|------|--------|
| 需要低比特权重部署且引擎支持 AWQ 路径 | 用开放聊天分代替 Agent 工具评测 |
| 与 Eval 门禁、金丝雀一起上线 | 当作「修好了规划/记忆」 |
