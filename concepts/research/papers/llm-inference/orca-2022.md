# Orca: A Distributed Serving System for Transformer-Based Generative Models

## Metadata

- Authors / Year / Venue: Yu et al. · OSDI 2022
- Links: https://www.usenix.org/conference/osdi22/presentation/yu

- Last reviewed: 2026-10-07

## TL;DR

提出 **iteration-level（连续）批处理**：生成式请求动态到达/完成时仍高效批执行。现代 LLM 连续批思想重要来源。

## Problem setup

请求级批处理在自回归生成中利用率差（长短请求互相拖累）。

## Method / Mechanism

调度粒度细化到 iteration；完成的序列离开 batch，新请求加入。

## How it changes the Agent Loop

- 纯 **推理数据面**；Agent Loop 只感受 TTFT/TPOT/队列。
- 与控制面分离：工具执行不在推理调度器内。

## Experiments that matter

- iteration-level（连续）批相对 request-level 批：长短生成并存时 GPU 利用率与吞吐更高（见 OSDI'22 原文对比）。
- 动态到达/完成下，完成序列可立即离批、新请求可加入——这是现代连续批的核心实证。
- 工程取用：用你的并发与长度分布重测 TTFT/TPOT，勿直接套原文吞吐数字当 SLO。

## Engineering takeaways

1. 多 Agent 并发时，引擎批处理决定尾延迟。
2. Obs 应分开记录 queue_wait vs model_time。
3. 连续批 + KV 池共同决定并发上限。

## Limitations & failure modes

- 调度不公导致长生成饿死。
- 与业务优先级需网关策略。

## When you should / shouldn't use it

| 应该 | 不应该 |
|------|--------|
| 自建高吞吐推理 | 混谈成 Agent 框架特性 |
