# Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks

## Metadata

- Authors / Year / Venue: Lewis et al. · 2020 · arXiv:2005.11401
- Links: https://arxiv.org/abs/2005.11401
- Tags: rag
- Last reviewed: 2026-10-07
- Reference: [paper-rag-2020](../../../references/papers.md#paper-rag-2020)

## TL;DR

把 **参数化生成模型** 与 **非参数化检索记忆**（稠密索引文档）联合：先检索再条件生成。奠定 RAG 术语与基本范式；Agent 场景中它是「取外部知识」子系统，不是 Memory / Context 本身。

## Problem setup

纯参数模型知识固化在权重中，难更新、易幻觉；知识密集型 NLP 需要可更换的外部记忆。

## Method / Mechanism

```text
Query → Retriever（稠密向量索引）→ Top-k docs
      → Generator（条件于 query + docs）→ Answer
```

论文讨论文档级边际化等变体；工程抽象保留「检索 → 增强生成」。

## How it changes the Agent Loop

- 通常作为 **Tool 或预取管道**：在 Decide 前/中注入证据。
- 不替代 Loop；检索结果是 **不可信观测**，需分区与引用。
- 与 Memory：RAG 面向语料库事实；Memory 面向跨会话选择性持久化。

## Experiments that matter

- 开放域问答等知识密集型任务上相对纯参数基线的增益（见原文）。
- 工程迁移时：索引新鲜度、切块、重排比「是否叫 RAG」更重要。

## Engineering takeaways

1. RAG ≠ 搜索 UI ≠ 数据库；核心是检索增强生成链路。
2. 注入 Context 前：去噪、引用、权限过滤（Security / Context）。
3. 评测拆开：检索指标 vs 端到端任务成功。
4. 知识截止问题用语料更新/工具，不靠更大生成模型单独解决。

## Limitations & failure modes

- 检索错 → 生成一本正经错（忠实性幻觉）。
- 顶 k 噪声导致 Lost-in-the-middle / 注意力稀释。
- 私有语料 ACL 泄漏若未做文档级权限。

## When you should / shouldn't use it

| 应该 | 不应该 |
|------|--------|
| 私有/易变知识、需引用 | 可用单次工具精确查询的权威系统（优先工具） |
| 知识库问答 | 把整库每次塞进窗口当「RAG」 |
