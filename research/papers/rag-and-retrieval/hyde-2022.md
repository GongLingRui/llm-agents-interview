# Precise Zero-Shot Dense Retrieval without Relevance Labels (HyDE)

## Metadata

- Authors / Year / Venue: Gao et al. · 2022 · arXiv:2212.10496
- Links: https://arxiv.org/abs/2212.10496
- Tags: rag
- Reference: [paper-hyde-2022](../../../references/papers.md#paper-hyde-2022)
- Last reviewed: 2026-10-07

## TL;DR

HyDE：先让 LLM 生成「假设文档」，再对该文档做嵌入检索真实语料——用文档邻域锚定，而不是直接嵌入短查询。是零样本稠密检索技巧，不是完整 RAG 系统。

## Problem setup

短查询与文档分布不匹配时，直接查询嵌入检索弱；又缺少相关性标注做训练。

## Method / Mechanism

```text
Query → LLM 生成假设回答/文档 → Embed(hyde_doc) → 检索真实索引 → 返回证据
```
假设文档不必事实正确；目标是落到与相关文档相近的向量区域。

## How it changes the Agent Loop

- 可插在 RAG 管道的 **Retriever 前/中** 作为查询改写变体。
- 不改变 Generator；增加一次生成成本与幻觉风险（假设文档噪声）。
- 与 Agent：可作为 `retrieve` 工具内部策略，不是 Memory。

## Experiments that matter

- 零样本稠密检索设定下，HyDE（假设文档嵌入）相对直接嵌入短查询有明显增益（见原文 BEIR 等；部署时在自有语料重跑）。
- 假设文档不必事实正确——收益来自落入相关文档邻域，而非「生成即答案」。
- 工程取用：多一次 LLM 调用换检索召回；需同时报延迟、检索命中与端到端，并防离题漂移。

## Engineering takeaways

1. 零样本/冷启动检索可试 HyDE，再与 BM25/稠密融合对比。
2. 必须评测：延迟 + 检索命中 + 端到端；HyDE 多一次 LLM 调用。
3. 假设文档不要直接当事实注入最终答案——只作检索锚。
4. 生产可用缓存：相同查询复用 hyde 向量。

## Limitations & failure modes

- 假设文档离题 → 检索漂移。
- 成本/延迟上升。
- 不解决权限与注入。

## When you should / shouldn't use it

| 应该 | 不应该 |
|------|--------|
| 冷启动稠密检索、短查询 | 已有强监督检索器或精确 ID 查询工具足够时 |
