# Tree of Thoughts: Deliberate Problem Solving with Large Language Models

## Metadata

- Authors / Year / Venue: Yao et al. · 2023 · arXiv:2305.10601
- Links: https://arxiv.org/abs/2305.10601
- Tags: reasoning-planning
- Last reviewed: 2026-10-07
- Reference: [paper-tot-2023](../../../references/papers.md#paper-tot-2023)

## TL;DR

把中间「thought」当作 **搜索树节点**：多路径生成候选、评估、扩展或回溯，而不是单条 CoT。对应工程上的 search/exploration 控制；**成本显著高于单链推理**，且不适合有不可逆工具副作用的默认路径。

## Problem setup

单链 CoT 无法探索替代路径，也难在中间步骤显式评估与回溯；对需「深思熟虑」分解的问题（谜题、规划式组合）脆弱。

## Method / Mechanism

```text
根问题
  → 生成多个 thought 候选（分支）
  → 启发式/模型自评对节点打分或投票
  → BFS / DFS 等策略扩展有希望的节点
  → 剪枝低分路径；必要时回溯
  → 叶节点或终止条件给出解
```

Thought = 连贯中间步骤单元（比单 token 粗、比完整答案细）。搜索算法与评估器可替换，核心是「多路径 + 中间评估」。

## How it changes the Agent Loop

| 环节 | 变化 |
|------|------|
| Decide | 从单次采样变为树搜索调度（生成/评估/选边） |
| Act | 论文主设定多为纯推理；若接工具，分支会放大副作用 |
| Terminate | 需显式预算：深度、宽度、节点数、token |

不替代 Memory/Tool；是 Reasoning 层的 **Exploration 策略**。

## Experiments that matter

- 相对 CoT / 自洽采样：在需探索与回溯的任务上更有优势（见原文设定；生产须用自有任务重测）。
- 工程关键量：节点扩展次数 × 每次调用成本，而非仅看最终准确率。

## Engineering takeaways

1. ToT = 可控搜索，不是「更长 CoT」；先定宽度/深度/评估预算。
2. 评估器质量决定剪枝；自评可错——高风险域加外部 verifier。
3. 有写库/发消息等副作用时，默认禁用盲目分支，或只在沙箱仿真中探索。
4. 与 Plan 对象：搜索轨迹可日志化，但生产 Plan 仍需结构化状态与权限，而非整棵树塞进 Context。

## Limitations & failure modes

- Token/延迟爆炸；易超时或超预算。
- 错误评估 → 剪掉正确枝或保留坏枝。
- 工具环境非幂等时，「探索」即真实损害。

## When you should / shouldn't use it

| 应该 | 不应该 |
|------|--------|
| 可逆、可评分的组合/谜题式子问题 | 默认对话或低延迟路径 |
| 离线规划草稿（无副作用） | 替代 RAG 事实检索 |
